## 1. 执行约定

### 1.1 范围与状态

**原“图床配置”页并入“上传图片”页；“图床设置”页继续保留。** Token 验证与仓库初始化归登录流程，目录配置归上传页弹窗，命名、压缩、水印、链接和部署偏好归图床设置。任何任务不得通过只隐藏导航、保留断开的旧跳转来完成合并。

任务中的“完成”复选框是唯一进度标记。只有实施内容、验收条件和验证证据全部满足后才能勾选；代码已编写但未验收时保持未勾选，并记录未完成项。本文新增文件、测试和验收记录路径均为后续交付要求，不表示这些文件已经创建。

全部路径相对项目根目录。每个阶段隐含依赖上一阶段通过准出检查；任务的“依赖”字段补充具体依赖，不能只按编号执行。P2 的路由切换 T015 必须在目录弹窗 T019 完成后收口，避免切换到尚未具备配置能力的上传页；P5 的 T038 部署状态服务先于 T036 的 Pages 来源选择接入。

清单编写阶段只编写文档。2026-10-16 起按用户指令执行 P0、P1、P2；2026-10-17 继续执行 P3、P4，2026-10-18 完成 P4 验收及 P5 实施，每完成一项任务生成一个 Git 提交；不改设计稿、不删除文件、不推送。执行前已重新核对工作区，具体状态见验收记录。

### 1.2 每个实现任务共同遵守的完成条件

1. 读取本任务触达的页面、路由、Store、API / 处理服务、持久化、多语言和样式调用链，仅修改必要部分。
2. 新代码使用 Vue Composition API 与明确的 TypeScript 类型；Props Down、Events Up，派生状态用 `computed`，不新增 `any`、类型忽略或掩盖问题的非空断言。
3. 用户文本同步简体、繁体、英文；界面使用语义 Token、统一图标与可见焦点，正文至少 14px、移动关键输入至少 16px、触摸目标至少 44×44px。
4. 对视觉变更检查桌面与 375px；对行为变更覆盖正常、加载、空、失败、离线、无权限或部分成功中适用的状态。任务阶段内完成，P6 再做整体验收。
5. 类型、API 结果或持久化契约变更先更新方案，再同步代码和调用方。复用既有算法、Pinia、浏览器存储键及云同步管线，不安排技术栈升级或插件化。
6. 运行与改动相关的检查，修复本任务引入的失败，记录原有失败。无需为纯样式添加镜像实现的测试；必须为目录事务、结果判定、选择范围等业务边界补充有效测试。
7. 不读取或分析 `node_modules`、`dist` 等禁止目录，不读取凭据文件，不输出 Token、OAuth code 或含凭据的错误对象，不手工编辑自动生成声明。

### 1.3 验证与记录规则

| 验证类型 | 执行方式与记录 |
| --- | --- |
| 静态检查 | `pnpm lint`、`pnpm lint:style`；仅文档任务检查结构、链接和覆盖关系 |
| 类型与业务测试 | `pnpm typecheck`、`pnpm test`；记录实际执行的目标与结果 |
| 构建与页面流程 | `pnpm build` 后执行 `pnpm test:e2e`；E2E 使用现有 preview 服务配置 |
| 阶段工程检查 | `pnpm verify` 包含 lint、stylelint、typecheck、单测、build；E2E 单独执行 |
| 视觉与交互 | 记录画板 ID、视口、语言、主题、浏览器和截图；不以静态检查代替视觉验收 |
| 真实远端 | T045、T046 记录真实环境和结果；mock、本地或定时器不能证明远端成功 |

建议从 T001 起建立 `docs/UI-REDESIGN-ACCEPTANCE.md`，每项只记录任务编号、实施提交、检查结果、证据路径、遗留项与回滚说明。测试数据使用脱敏 fixture。真实上传、初始化仓库、部署、重建分支、删除媒体或 CNAME，须在已有明确授权范围内执行；无授权或环境时记录待验证，不勾选相关验收任务。
